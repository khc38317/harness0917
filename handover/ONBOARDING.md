## 🎯 5분 안에 이해하기

### 이것이 무엇인가?

회의록 기반 **SSOT(Single Source of Truth)** 시스템입니다.
- 회의에서 나온 **의사결정**을 체계적으로 기록
- **액션아이템**의 상태를 추적
- 모든 것에 **출처**를 기록 (어느 회의에서 나왔는지)

### 왜 필요한가?

```
❌ 과거: 회의록 여러 곳 → 의사결정 어디 있지? → 액션 누가 하기로?
✅ 지금: wiki → 결정 명확 → 액션 진행중 → 완료
```

### 3가지 파일만 기억하면 됨

| 파일 | 용도 | 예시 |
|---|---|---|
| **D-XXXX.md** | "이 결정을 했다" | D-0001: Q2 로드맵 확정 |
| **actions.md** | "이걸 누가 언제까지" | A-0001: 박준서가 5/21까지 스펙 확보 |
| **index.md** | "지금 상태는?" | 마지막 D는 D-0006, 마지막 A는 A-0008 |

## 🤔 헷갈릴 수 있는 부분

### "원본 회의록은 어디?"

**raw/** 폴더에 있습니다. (절대 수정 금지!)

```
raw/2026-04-16-제품주간회의.md  ← 원본 (SSOT)
wiki/meetings/2026-04-16-제품주간회의.md  ← 사본 (읽기용)
```

### "D와 A 번호가 빠지는 것 같은데?"

정상입니다. 번호는 증가만 합니다.
- 완료된 A도 번호는 유지됩니다.
- 번복된 D도 번호는 유지됩니다.

예: A-0001 완료, A-0002 취소 → 다음은 A-0003

### "왜 출처 링크가 필요하지?"

회의록이 틀렸을 때 원문을 바로 찾기 위함입니다.

```
❌ "Q2 목표는 뭐라고 했어?"
✅ "Q2 목표는 뭐다 [[2026-04-16]]" 
   → 회의록 열어서 확인 가능
```

## ⚠️ 절대 금지

| 금지 | 이유 |
|---|---|
| raw/YYYY-MM-DD-*.md 수정 | SSOT 원본 변경 금지 |
| 완료된 액션 번호 재사용 | ID 관리가 복잡해짐 |
| 출처 링크 생략 | 나중에 원문 찾을 수 없음 |
| 규칙 무시 ("이번만") | 시스템 신뢰도 하락 |

## 💬 자주 묻는 질문 (FAQ)

### Q: D-0001을 수정하고 싶은데?

A: 수정하지 말고, **D-0005 같은 새 파일을 만들어서** 이전 결정이 변경되었다고 기록합니다.

**예**: 결제 일정 변경
- ❌ D-0001 수정하기 (금지)
- ✅ D-0005 생성하고 "D-0001의 일정을 6월 중순 → 7월 초로 변경" 기록

### Q: 결정이 여러 번 바뀌면?

A: 이슈 등록합니다.

**규칙**: 같은 항목이 2회 이상 연기되면
→ `wiki/meetings/open-items.md`에 이슈 등록

### Q: 새로운 용어가 나오면?

A: `wiki/glossary.md`에 추가합니다.

형식:
```markdown
| A/B 테스트 | AB테스트, 분할테스트 | 2개 이상 방안을 검증 | [[2026-06-11]] | [[D-0006]] |
```

### Q: 액션이 완료되지 않으면?

A: 상태를 "보류" 또는 "대기중"으로 변경합니다.

상태 옵션: `진행중` / `대기중` / `보류` / `완료` / `취소됨`
