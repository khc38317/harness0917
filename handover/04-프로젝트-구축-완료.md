## 설계 하이라이트

### ✨ 5가지 핵심 원칙

1. **raw = SSOT** (불변의 기준)
2. **wiki = 협업** (LJM + 사람)
3. **규칙 = 사람 소유** (우회 불가)
4. **출처 추적** (([[YYYY-MM-DD]]))
5. **ID는 증가만** (절대 중복 금지)

### 🛡️ 4가지 운영 리스크 + 보완책

1. **actions.md 병목** → 분기별 아카이브
2. **ID 충돌** → State 확인 단계
3. **출처 규칙 경직성** → Bullet point 단위
4. **용어 정규화 미흡** → 동의어 관리

### 🔐 명확한 소유권

| 경로 | LJM | 사람 |
|---|---|---|
| wiki/meetings/ (원본) | 읽기만 | 원본 작성 |
| wiki/meetings/*.md (메타) | 생성/갱신 | 검토 |
| CLAUDE.md | 제안 | 승인/수정 |
| SCHEMA.md | 제안 | 승인/수정 |
| commands/ | 실행 | 변경 승인 |

## 주의사항

### 절대 금지 ❌
- wiki/meetings/YYYY-MM-DD-*.md 수정/삭제
- ID 뒤로 가기 (D-0001 → D-0002만 가능)
- LJM이 규칙 우회 ("효율성 때문에", "이번만")
- 규칙 명시 없이 ingest 프롤로그 변경

### 필수 ✅
- 매 /ingest 전에 index.md의 "현재 상태" 읽기
- 모든 사실에 출처 링크 붙이기 ([[YYYY-MM-DD]])
- 결정 번복 시 새 D 생성 (기존 D 수정 금지)
- 분기별 완료 액션 아카이브 (6개월 후부터)
