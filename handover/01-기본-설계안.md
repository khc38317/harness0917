# 01. 기본 설계안

**작성일**: 2026-09-17  
**목적**: 회의록 기반 SSOT 구축 - 기본 설계 개요

---

## 개요

**Wiki Harness**는 Notion에서 내보낸 회의록을 원본으로 하여 의사결정과 액션아이템을 추적하는 시스템입니다.

---

## 3가지 핵심 원칙

### 1️⃣ raw = SSOT (불변)
- 원본 회의록은 절대 수정 불가
- LJM은 읽기만 가능
- Git으로 모든 변경 추적

### 2️⃣ wiki = LJM 소유, 사람 검토
- LJM이 빠르게 생성/갱신
- 사람이 품질 검토 + 승인
- 협업으로 신뢰도 높음

### 3️⃣ 규칙은 사람만 변경
- CLAUDE.md, SCHEMA.md는 사람만 수정
- LJM은 제안만 가능
- 규칙 우회 금지

---

## 디렉토리 구조

```
wiki_harness/
├─ CLAUDE.md              # 도구 설명
├─ SCHEMA.md              # 포맷 정의
├─ README.md              # 빠른 시작
├─ OBSIDIAN_SETUP.md      # Obsidian 설정
│
├─ raw/                   # (비어있음)
│
├─ wiki/
│  └─ meetings/           # 모든 것이 여기!
│     ├─ YYYY-MM-DD-*.md  # 원본 회의록 (불변)
│     ├─ decisions.md     # 결정 목록
│     ├─ actions.md       # 액션아이템
│     ├─ index.md         # 카탈로그
│     ├─ log.md           # 운영 기록
│     ├─ open-items.md    # 미결 사항
│     └─ glossary.md      # 용어/시스템명
│
└─ .claude/commands/
   ├─ ingest.md
   ├─ lint.md
   └─ brief.md
```

---

## 7가지 .md 파일의 역할

| # | 파일 | 역할 | 관리 |
|---|---|---|---|
| 1️⃣ | YYYY-MM-DD-*.md | 원본 회의록 | 사람 작성, 절대 수정 금지 |
| 2️⃣ | decisions.md | 결정 목록 (D-XXXX) | LJM 생성, 사람 검토 |
| 3️⃣ | actions.md | 액션아이템 (A-XXXX) | LJM 생성, 사람 검토 |
| 4️⃣ | index.md | 전체 카탈로그 + 상태 | LJM 갱신 |
| 5️⃣ | log.md | 운영 기록 (append-only) | LJM append |
| 6️⃣ | open-items.md | 미결 사항 | LJM 관리 |
| 7️⃣ | glossary.md | 용어/시스템명 | LJM 관리 |

## 3개 커맨드

### /ingest
회의록 1건을 읽고 메타 파일 자동 갱신

```
/ingest wiki/meetings/YYYY-MM-DD-제목.md
```

**결과**:
- decisions.md 갱신
- actions.md 갱신
- glossary.md 갱신
- index.md 갱신
- log.md append

### /lint
위키 건강도 검사

```
/lint
```

**검사 항목**:
- 출처 링크 누락
- 기한 임박/초과 액션
- 좀비 액션 (30일 비활동)
- 미결 사항 미배정
- 용어 일관성
- 포맷 오류
- ID 중복

### /brief
다음 회의 전 브리핑

```
/brief
```

**출력**:
- 기한 임박 액션
- 진행 중인 액션
- 최근 번복된 결정
- 미해결 질문
- 추천 아젠다

## 워크플로우

```
1️⃣ 회의 진행
   ↓
2️⃣ 회의록 저장: wiki/meetings/YYYY-MM-DD-*.md
   ↓
3️⃣ /ingest 실행
   ├─ LJM: 분석 + 갱신
   ├─ 사람: 검토 + 피드백
   ├─ LJM: 수정
   └─ 사람: 승인 + commit
   ↓
4️⃣ 메타 파일 갱신 완료
   ↓
5️⃣ 다음 회의 전 /brief 실행
   ↓
6️⃣ (선택) /lint 실행
```

## ID 규칙

### D (결정)
- 형식: D-0001, D-0002, ...
- 증가만 가능 (절대 뒤로 갈 수 없음)
- 번복 시: 새 D 생성 + 이전 D에 표시

### A (액션)
- 형식: A-0001, A-0002, ...
- 증가만 가능 (절대 뒤로 갈 수 없음)
- 완료된 ID는 재사용 불가

**State 확인**:
매 /ingest 전에 `wiki/meetings/index.md`에서 마지막 번호 확인 후 +1부터 시작
