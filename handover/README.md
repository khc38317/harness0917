## ⚡ 핵심 조언

### 설계 원칙 3가지

1. **원본은 불변 (raw = SSOT)**
   - wiki/meetings/YYYY-MM-DD-*.md는 절대 수정하지 않기
   - 오류가 있어도 새 항목으로만 추가

2. **협업이 신뢰를 만든다**
   - LJM이 빠르게 만들고 → 사람이 검토 → LJM이 수정 → 사람이 승인
   - 병렬이 아니라 **순차 협업**

3. **규칙은 사람만 변경**
   - LJM은 규칙을 따르기만 함
   - 규칙을 개선하는 건 사람의 책임

### 첫 실수 Top 3 (피하기)

❌ **실수 1**: 원본 회의록 수정
```
잘못된 것: wiki/meetings/2026-03-12-주간개발.md를 나중에 수정
올바른 것: 새로운 회의 회의록에서 "2026-03-12 회의록 오류 정정" 항목 추가
```

❌ **실수 2**: LJM이 규칙을 우회
```
잘못된 것: "/ingest에서 효율성 때문에 State 확인 단계 생략"
올바른 것: CLAUDE.md에서 규칙 자체를 사람에게 제안
```

❌ **실수 3**: ID 충돌
```
잘못된 것: index.md 없이 D-0001, A-0001 중복 할당
올바른 것: 매번 index.md의 "현재 상태"에서 마지막 번호 확인
```
