**최종 갱신**: 2026-06-11  
**상태**: 운영 중

## 📌 개요

이 문서는 Wiki Harness 프로젝트에서 정한 모든 규칙, 프로토콜, 의사결정을 정리합니다.  
새로운 팀원이나 LJM(Large Language Model)이 참여할 때 참고하세요.

---

## 🔑 핵심 원칙 5가지

### 1. wiki/meetings = SSOT (불변의 원천)

- **원본 회의록**: 사람만 작성 (Notion .md 내보내기)
- **메타 파일**: LJM이 생성 (decisions.md, actions.md 등)
- **읽기 권한**: LJM은 읽기만 가능
- **변경**: Git으로 모든 변경 추적

→ **원본이 바뀌면 SSOT가 무너지므로 절대 수정 불가**

---

### 2. wiki/meetings/ = LJM이 소유, 사람이 검토

- **생성**: LJM이 회의록 분석해서 decisions.md, actions.md 갱신
- **검토**: 사람이 파싱 오류/분류 오류 인라인 수정
- **승인**: 최종 OK 후 commit

→ **LJM이 빠르게 만들고, 사람이 품질 보증**

---

### 3. 규칙은 사람만 변경 (LJM은 제안만)

- **CLAUDE.md**: 커맨드 정의 (사람만 수정)
- **SCHEMA.md**: 포맷 정의 (사람만 수정)
- **scripts/**: 검사 규칙 (사람만 수정)

→ **LJM이 "효율성 때문에" 규칙을 우회하면 신뢰도 하락**

---

### 4. 출처 추적은 필수

모든 진술이 어느 회의에서 나왔는지 `[[YYYY-MM-DD]]` 링크로 기록

→ **wiki가 틀렸을 때 원문을 바로 확인 가능**

---

### 5. ID는 증가만 (중복 금지)

- D: D-0001, D-0002, ... (절대 뒤로 갈 수 없음)
- A: A-0001, A-0002, ... (절대 뒤로 갈 수 없음)

→ **index.md의 "현재 상태"를 항상 읽고 +1부터 시작**

---

## ⚙️ LJM의 행동 규칙

### ✅ 할 수 있는 것

- wiki/meetings/ 메타 파일 생성/갱신 (SCHEMA.md 틀 안에서)
- 규칙 실행 (CLAUDE.md/SCHEMA.md 정의대로)
- 명확한 오류 보고 (규칙 위반 플래그)
- 개선 제안 (사람이 승인 필수)

### ❌ 절대 안 되는 것

- CLAUDE.md 규칙 우회 ("효율성 때문에", "이번만")
- SCHEMA.md 해석 ("이 경우는 포맷을 빼도 괜찮을 것 같아요")
- 검사 규칙 수정 ("이 출처 링크는 생략하겠습니다")
- wiki/meetings/YYYY-MM-DD-*.md 수정/삭제 (원본 회의록)
- 불명확한 상황에서 임의 판단 후 진행

---

## 🤔 모호한 상황 처리 프로토콜

규칙에 없거나 불명확한 상황이 발생하면:

1. **즉시 중단** → 진행하지 말기
2. **상황 설명** → 뭐가 불명확한지 명확히
3. **옵션 제시** → 가능한 방식 2~3개 제안
4. **사용자 선택 대기** → 사용자 확인 후에만 진행
5. **확인 후 실행** → 승인받은 방식대로만 실행

### 예시

```
[규칙 없음 상황 발생]
LJM: "이 경우는 규칙에 없습니다.
옵션 A: 이렇게 할 수 있고,
옵션 B: 저렇게 할 수 있습니다.
어느 쪽이 맞을까요?"

[사용자 선택]
사용자: "옵션 A로"

[확인 후 실행]
LJM: "옵션 A로 진행하겠습니다" → 실행
```

## 📋 일정 연장 추적 규칙

**목적**: 같은 항목이 반복 연장되는 것을 감지하고 이슈화

### 정의

- **1회 연장**: 일정 변경은 정상 (D-000X 신규 결정으로 기록)
- **2회 이상 연장**: 같은 항목이 기한 연기 2회 이상 → **open-items.md에 이슈 등록**

### 추적 방법

각 D 페이지의 "수정 기록"에서:

```
## 수정 기록

- [[D-0005]]가 이를 수정함 (6월 중순 → 7월 초)
```

### 이슈 등록 기준

**결제 연동 일정 예시**:
```
- D-0001: 5월 말 (최초)
- D-0004: 6월 중순 (1회 연장 - 정상)
- D-0005: 7월 초 (2회 연장 - ⚠️ open-items.md에 등록)
```

### 이슈 등록 내용

**open-items.md 이슈 추적 테이블**:
```
| 항목 | 원래 기한 | 1차 연장 | 2차 연장 | 근본 원인 | 상태 |
|---|---|---|---|---|---|
| 결제 연동 | D-0001 | D-0004 | D-0005 | PG사 응답 지연 | 🚨 추적 중 |
```

## 📂 파일 구조 & 담당

| 파일/디렉토리 | LJM 권한 | 사람 권한 | 용도 |
|---|---|---|---|
| **raw/** | - | 원본 저장 | 회의록 원본 보관 |
| **wiki/meetings/YYYY-MM-DD-*.md** | 읽기 | 작성 | 원본 회의록 (SSOT) |
| **wiki/decisions/D-XXXX-*.md** | 생성/갱신 | 검토 | 의사결정 기록 |
| **wiki/actions/actions.md** | 생성/갱신 | 검토 | 액션아이템 관리 |
| **wiki/glossary.md** | 생성/갱신 | 검토 | 용어 정의 |
| **wiki/meetings/index.md** | 갱신 | 검토 | 상태 추적 (D, A 번호) |
| **wiki/meetings/log.md** | append | - | 운영 기록 (읽기전용) |
| **wiki/meetings/open-items.md** | 갱신 | 검토 | 미결 사항 + 이슈 추적 |
| **CLAUDE.md** | 제안 | 수정 | LJM 규칙 정의 |
| **SCHEMA.md** | 제안 | 수정 | 포맷 정의 |

## 🔄 /ingest 프로토콜 (간략)

### 사전 확인

1. **index.md에서 마지막 D, A 번호 읽기**
2. **회의록 전문 분석**

### 추출 & 검증

3. **결정/액션/용어 추출**
4. **사용자에게 결과 제시 & 검증**

### 파일 생성/갱신

5. **D 페이지 생성** (wiki/decisions/)
6. **actions.md 갱신** (열린 액션, 완료 액션)
7. **glossary.md 갱신** (신규 용어)
8. **index.md 갱신** (D, A 번호, 회의 기록)
9. **log.md append** (운영 기록)
10. **open-items.md 갱신** (미결, 이슈 추적)

### Commit

11. **git commit** (규칙: `ingest: YYYY-MM-DD 회의명`)
