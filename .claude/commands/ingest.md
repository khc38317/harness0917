# /ingest — 회의록 수집 및 처리

**목적**: wiki/meetings/ 원본 1건을 읽고 → wiki 페이지 자동 생성

**사용법**:
```
/ingest wiki/meetings/YYYY-MM-DD-제목.md
```

---

## 🔄 프로토콜 (반드시 이 순서대로)

### 1️⃣ State 확인 (필수!)

먼저 다음 파일을 읽으세요:

```
index.md에서:
- "마지막 할당된 D 번호" 확인
- "마지막 할당된 A 번호" 확인
```

예시:
```
index.md가 이렇게 되어 있다면:

- 마지막 할당된 D 번호: D-0005
- 마지막 할당된 A 번호: A-0020

→ 새 결정은 D-0006부터 시작
→ 새 액션은 A-0021부터 시작
```

**절대 중복하면 안 됩니다.**

---

### 2️⃣ 회의록 읽기

제공된 파일명의 원본을 전문 읽기:
```
wiki/meetings/YYYY-MM-DD-제목.md
```

내용 분석:
- **의제** (agenda)
- **논의 및 결정** (decisions made)
- **액션아이템** (action items)
- **미결 사항** (open questions)
- **신규 용어/시스템명** (new terminology)

---

### 3️⃣ 추출 및 정규화

#### 결정 (Decision) 추출

회의에서 "**결정됨**", "**정하기로 함**", "**변경**" 등 명시적인 결정을 찾습니다.

```
예시:
"JWT 기반 인증을 세션 기반으로 변경하기로 결정했다."
→ D-0006: 인증 방식을 JWT에서 세션으로 변경

"결제 기능은 추가 검토 필요해서 Q2 로드맵에서 제외."
→ D-0007: 결제 기능을 Q2 로드맵에서 제외
```

각 D마다:
- 제목 (명사형 또는 과거형)
- 상태: `확정` (회의에서 결정된 것)
- 담당: 구현/관리할 사람 (명시되지 않으면 PM)
- 기한: 회의에서 언급된 기한 (없으면 비워두기)

#### 액션아이템 (Action) 추출

회의에서 "**하기로 함**", "**누가 ~까지**", "**다음 주에 확인**" 등 할 일을 찾습니다.

```
예시:
"Bob이 인증 PoC를 3월 19일까지 구현하기로"
→ A-0021: PoC — 세션 기반 인증 구현
   담당: Bob
   기한: 2026-03-19
   상태: 진행중

"Alice: 결제 팀과 미팅 예약해달라"
→ A-0022: 결제 팀 미팅 예약
   담당: Alice
   기한: (명시 없음)
   상태: 진행중
```

각 A마다:
- 제목 (동사형)
- 담당: 명시된 사람
- 기한: 명시된 날짜 (없으면 비워두기)
- 상태: 항상 `진행중` (새 액션)

#### 미결 사항 (Open Question)

"**다음 회의서 논의**", "**추후 결정**", "**조사 필요**" 등 미해결 항목

```
예시:
"세션 저장소는 Redis vs DB 조사 후 다음에 정하자"
→ 미결: "세션 저장소: Redis vs DB"
   → 책임자: Bob (조사하기로)
   → 다음 회의에서 A로 전환될 가능성
```

#### 신규 용어 추출

회의에서 처음 등장하거나 팀이 자주 쓰는 단어

```
예시:
"JWT", "PoC", "마이그레이션", "Redis", "세션 저장소"
→ 각각 glossary.md에 추가 (또는 기존 동의어로 병합)
```

### 4️⃣ 사용자 검증 단계 (꼭 필요!)

추출 결과를 명확하게 제시합니다:

```
📋 [2026-03-12-주간개발] 추출 결과

✅ 신규 결정:
- D-0006: 인증 방식을 JWT에서 세션으로 변경
- D-0007: 결제 기능을 Q2 로드맵에서 제외

✅ 신규 액션:
- A-0021: PoC — 세션 기반 인증 구현 (Bob, 기한: 2026-03-19)
- A-0022: 세션 기반 FE 연동 검토 (Carol, 기한: 2026-03-19)
- A-0023: 세션 저장소 비교 분석 (Bob, 기한: TBD)

✅ 신규 용어 (3개):
- JWT (동의어: -) — 기존 용어는 아님
- PoC (동의어: -) — 신규 추가
- Redis (동의어: -) — 신규 추가

✅ 미결 사항:
- "세션 저장소: Redis vs DB" → A-0023으로 배정됨
- "기존 사용자 마이그레이션 전략" → 아직 미결

🤔 확인 사항:
- "기한이 명시 안 된 액션" A-0022 (Carol의 FE 검토)는 몇 일까지일까요?
- D-0007의 담당을 PM으로 하는 게 맞을까요?

이대로 진행할까요? (Y/N)
```

사용자의 피드백을 받으면:
- ✅ Y → 다음 단계로 진행
- ❌ N (또는 피드백) → 수정 후 다시 제시

**상태**: 확정
**담당**: Bob (Backend)
**기한**: 2026-03-31
**출처**: [[2026-03-12]]

## 결정 내용

JWT 기반 인증을 세션 기반으로 변경한다. [[2026-03-12]]

## 검토한 대안

1. JWT 유지 + 블랙리스트 관리 (거절됨)
   - 비용: 높음, Redis 추가 필요 [[2026-03-12]]
   - 기존 사용자 revoke 불가 [[2026-03-12]]

2. **세션 기반** (채택됨) ✅
   - 기존 인프라 활용 가능 [[2026-03-12]]
   - 기존 사용자 revoke 가능 [[2026-03-12]]

## 근거

- 현재 사용자 탈퇴 시 토큰 폐기 방법 없음 [[2026-03-12]]
- 팀 인프라와 호환성 좋음 [[2026-03-12]]

## 영향받는 항목

- 액션: [[A-0022]] (Carol의 FE 연동)

## 📌 주의사항

### ID 충돌 방지 (중요!)
- State를 **항상 먼저** 읽으세요
- 새 번호는 **항상 +1**부터 시작하세요
- 중복되지 않는지 확인하고 진행하세요

### 출처 링크 (필수)
- 모든 진술에 `[[YYYY-MM-DD]]` 링크 필수
- 헤더나 메타데이터는 제외
- SCHEMA.md의 규칙 확인

### 규칙 우회 금지 (절대)
- "이 경우는 포맷을 생략해도 될 것 같아요" ❌
- "효율성 때문에 상태를 한두 개만 추가하겠습니다" ❌
- 규칙이 부족하면 **사람에게 물어보세요**

### 미결 사항 처리
- 미결이 명확한 책임자가 있으면 A로 변환
- 책임자 없으면 "다음 회의서 논의" 표시
- brief에서 "미해결 질문" 섹션에 올라옴
