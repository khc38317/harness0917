# /lint — 위키 건강도 검사

**목적**: wiki 전체를 스캔하고 문제를 플래그

**사용법**:
```
/lint
```

---

## 🔍 검사 항목 (순서대로 실행)

### 1️⃣ 출처 링크 검사

**규칙**: SCHEMA.md 참고

✅ **필수 (출처 링크 필수)**
- D 페이지의 모든 진술 (decision content, alternatives, reasoning)
- A 페이지의 모든 설명 bullet point
- glossary의 모든 정의 행

❌ **불필요 (출처 링크 선택)**
- 헤더 (예: `## 결정 내용`)
- 메타데이터 (예: `**상태**: 확정`)
- 테이블 헤더
- 순수 구조 데이터 (날짜, 숫자)

**보고 형식**:
```
출처 링크 누락 찾음 (N개):

❌ wiki/decisions/D-0006-인증방식변경.md:
   Line 15: "기존 사용자 revoke 가능" → [[YYYY-MM-DD]] 추가하세요
   Line 22: "팀 인프라와 호환성 좋음" → [[YYYY-MM-DD]] 추가하세요

❌ wiki/actions/actions.md:
   Line 78: "초기 설계 완료" → [[YYYY-MM-DD]] 추가하세요
```

---

### 2️⃣ 기한 임박 액션 검출

**조건**: 기한이 3일 이내

```
⚠️ 기한 임박 (3일 이내):

- A-0023 (Bob): 세션 저장소 분석
  기한: 2026-03-15 (오늘로부터 2일)
  상태: 진행중

- A-0024 (Alice): 결제 팀 재미팅
  기한: 2026-03-16 (오늘로부터 3일)
  상태: 대기중

→ 회의 아젠다에 추가하세요
```

---

### 3️⃣ 기한 초과 액션 검출

**조건**: 기한이 오늘보다 이전

```
❌ 기한 초과:

- A-0020 (Carol): FE 테스트
  기한: 2026-03-10 (5일 초과)
  상태: 진행중
  최근 업데이트: 2026-03-08

→ 기한을 연장하거나 상태를 확인하세요
```

---

### 4️⃣ 좀비 액션 검출

**조건**: 30일 이상 상태 변경이 없는 액션

```
🔄 활동이 없는 액션 (30일 이상):

- A-0015 (Bob): Legacy API 마이그레이션
  상태: 진행중
  마지막 업데이트: 2026-02-10 (35일 전)
  기한: 2026-03-31

→ "정말 진행 중일까요? 상태를 확인하세요"
```

---

### 5️⃣ 미결 사항 중 액션 미배정

**규칙**: 미결 사항이 있으면 누가 담당할 액션이 있어야 함

```
📌 미결 사항 중 액션 미배정:

회의: [[2026-03-12]]
- "세션 저장소: Redis vs DB"
  → Action: [[A-0023]] (Bob이 조사 중) ✅

- "기존 사용자 마이그레이션 전략"
  → Action 없음 ❌
  → "누가 이것을 조사하기로 했을까요?"
```

---

### 6️⃣ 용어 일관성 검사

**규칙**: glossary.md에서 동의어로 지정된 용어가 wiki에서 섞여 쓰이면 경고

```
⚠️ 용어 일관성 문제:

glossary.md에 정의:
- 정규형: "스펙"
- 동의어: "스팩, specification"

발견된 문제:
- D-0006: "스팩"이 2번 등장 (정규형 사용 안 함)
- A-0021: "specification"이 1번 등장

→ "스펙"으로 정규화할까요?
```

---

### 7️⃣ D (결정) 포맷 검사

**규칙**: SCHEMA.md 확인

각 D 페이지가 다음을 가져야 함:
- ✅ `# D-XXXX: 제목`
- ✅ `**상태**: [확정|잠정|논의중|보류|번복됨]`
- ✅ `## 결정 내용` 섹션
- ✅ `## 검토한 대안` 섹션
- ✅ `## 근거` 섹션
- ✅ `## 번복 기록` 섹션

```
❌ 포맷 오류:

- D-0006: "## 검토한 대안" 섹션 누락
- D-0007: "**기한**" 필드 누락 (선택이므로 OK)
- D-0008: "## 근거" 섹션에 내용이 비워있음
```

---

### 8️⃣ 액션 (A) 포맷 검사

**규칙**: wiki/actions/actions.md 구조

각 액션 엔트리가 다음을 가져야 함:
- ✅ `### A-XXXX: 제목`
- ✅ `**담당**: {이름}`
- ✅ `**기한**: YYYY-MM-DD` (선택)
- ✅ `**상태**: [진행중|대기중|보류|완료|취소됨]`
- ✅ `**출처**: [[YYYY-MM-DD]]`
- ✅ `**관련 결정**: [[D-XXXX]]` (있으면)

```
⚠️ 포맷 이상:

- A-0021: 기한이 명확하지 않음
- A-0022: 상태가 명확하지 않음
- A-0025: 출처 링크가 없음
```

---

### 9️⃣ D와 A의 연결 확인

**규칙**: 결정이 있으면 관련 액션이 있어야 함 (대부분)

```
⚠️ 연결 이상:

- D-0001: "결정했다" but 관련 A가 없음
  → 이게 설계만 하는 결정일까요? (OK)
  → 아니면 실행 액션이 필요한데 빠졌을까요? (확인 필요)

- A-0015: 관련 D가 명시 안 됨
  → "이 액션이 어느 결정에서 나왔을까요?"
```

---

### 🔟 ID 중복 검사

**규칙**: 같은 ID가 두 번 이상 나오면 안 됨

```
❌ ID 충돌:

- D-0001이 2개 파일에서 발견:
  1. wiki/decisions/D-0001-인증방식변경.md
  2. wiki/decisions/D-0001-결제제외.md (잘못된 ID!)

→ 두 번째 파일을 D-0008로 이름 변경하세요
```

## 📋 완전한 검사 결과 예시

```
===== /lint 검사 결과 =====

검사 대상:
- D 페이지: 8개
- A 페이지: 23개 (열림), 5개 (완료)
- 용어: 15개

✅ 통과 항목:
- 포맷 검사: 통과
- ID 중복: 없음
- 기한 초과 액션: 없음

⚠️ 경고 (조치 권장):
- 출처 링크 누락: 3개 (D-0006:2개, A-0021:1개)
- 기한 임박: 2개 (A-0023, A-0024)
- 좀비 액션: 1개 (A-0015, 35일 비활동)
- 용어 일관성: "스펙/스팩" 혼용 2개

❌ 오류 (반드시 수정):
- 기한 초과: 1개 (A-0020, 5일 초과)
- D-A 연결 이상: 1개 (D-0001의 관련 액션 없음)

===== 권장 조치 =====

우선순위 1 (반드시):
1. A-0020의 기한 연장 또는 상태 확인
2. D-0001의 관련 액션 확인

우선순위 2 (강력 권장):
3. D-0006, A-0021의 출처 링크 추가
4. A-0023, A-0024를 다음 회의 아젠다에 추가

우선순위 3 (선택):
5. 용어 "스팩" → "스펙"으로 정규화
6. A-0015의 진행 상황 체크

===== 전체 건강도 =====

점수: 85/100

- 구조: 95/100 ✅
- 추적성: 80/100 ⚠️ (출처 누락)
- 활동성: 88/100 ⚠️ (좀비 액션 1개)
- 일관성: 92/100 ⚠️ (용어 혼용)

===== 다음 /lint 권장 =====

1주일 후 또는 다음 회의 후
(기한 임박 액션 상태 확인)
```
