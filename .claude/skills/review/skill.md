# Wiki Harness LLM Review 스킬

이 스킬은 기계 검증(스크립트)이 아닌 **의미 수준의 컨텐츠 검증**을 수행합니다.

## 검증 대상

### 1단계: 회의록과 decisions.md 비교

**확인 항목**:
- ✅ 모든 결정이 기록되었는가?
- ✅ 회의록에 없는 내용이 decisions.md에 추가되었는가?
- ✅ 각 결정에 정확한 출처([[YYYY-MM-DD]])가 있는가?
- ✅ 결정 내용이 원문과 일치하는가?
- ✅ 대안 검토(검토한 대안)가 정확하게 기록되었는가?

**출력 형식**:
```
📋 Decisions Review

회의록: [[YYYY-MM-DD-회의명]]
상태: [✅ 통과 | ⚠️ 경고 | ❌ 오류]

✅ 통과한 결정:
- D-XXXX: 제목

⚠️ 경고:
- D-XXXX: 내용이 회의록과 약간 다름
  회의록: "..."
  wiki: "..."

❌ 누락:
- 회의록에서 발견: "결정명" (D 파일 없음)

❌ 출처 오류:
- D-XXXX: 잘못된 출처 또는 추가 출처 필요
```

### 2단계: 회의록과 actions.md 비교

**확인 항목**:
- ✅ 모든 액션이 기록되었는가?
- ✅ 회의록에 없는 액션이 추가되었는가?
- ✅ 담당자가 정확하게 기록되었는가?
- ✅ 기한이 정확하게 기록되었는가?
- ✅ 각 액션에 정확한 출처([[YYYY-MM-DD]])가 있는가?
- ✅ 액션의 상태가 정확하게 추적되었는가? (열림, 완료, 홀드, 조용히 사라짐 등)

**상태 추적 확인**:
```
액션 추적 체크리스트:
- 신규 액션인가? → 상태: 진행중/대기중
- 완료된 액션인가? → 상태: 완료
- 기한이 연장되었는가? → 새 A 항목 생성 또는 최근 업데이트 기록
- 어떤 이유로 더 이상 진행 안 하는가? → 상태: 취소됨 또는 보류
```

**출력 형식**:
```
✅ Actions Review

회의록: [[YYYY-MM-DD-회의명]]
상태: [✅ 통과 | ⚠️ 경고 | ❌ 오류]

✅ 통과한 액션:
- A-XXXX: 제목 (담당: 이름, 기한: YYYY-MM-DD)

⚠️ 경고:
- A-XXXX: 기한이 회의록과 다름
  회의록: "~6/18"
  wiki: "2026-06-28"

❌ 누락:
- 회의록에서 발견: "누군가 ~ (기한)"

❌ 상태 추적 오류:
- A-XXXX: 기한이 지났으나 상태가 여전히 "진행중"
  마지막 업데이트: 2026-06-15

❌ 조용한 사라짐:
- A-XXXX: 마지막 언급: 2026-06-11, 그 이후 상태 변경 없음
  현재 상태: "진행중" (90일 비활동)
```

### 3단계: 회의록과 glossary.md 비교

**확인 항목**:
- ✅ 회의록에서 새로 나온 용어가 모두 기록되었는가?
- ✅ 용어의 정의가 정확한가?
- ✅ 신규 약어/팀용어의 출처가 정확한가?

**출력 형식**:
```
📖 Glossary Review

회의록: [[YYYY-MM-DD-회의명]]
상태: [✅ 통과 | ⚠️ 경고 | ❌ 오류]

✅ 통과한 용어:
- A/B 테스트

⚠️ 경고:
- UX: 정의가 불충분 (더 자세한 설명 필요)

❌ 누락:
- 회의록에서 발견: "QA" (glossary에 없음)
```

### 4단계: 종합 컨텐츠 검증

**확인 항목**:
- ✅ 회의록에만 있는 내용? (decisions.md, actions.md에 빠진 것?)
- ✅ wiki에만 있는 내용? (회의록에 없는데 생성한 것?)
- ✅ 의역된 부분? (원문과 의미가 다른 부분)
- ✅ 중요한 컨텍스트 누락?

**출력 형식**:
```
🎯 종합 검증

회의록: [[YYYY-MM-DD-회의명]]
상태: [✅ 통과 | ⚠️ 경고 | ❌ 오류]

✅ 종합 평가:
- 회의록 커버율: 95%
- 정확도: 98%

⚠️ 주요 경고:
1. A-0001 "온보딩 개선"과 D-0007 "버전B 적용"의 연관성이 명시되지 않음
2. 회의 중간에 "예산 제약" 언급이 있었으나 근거에 포함되지 않음

❌ 치명적 오류:
- 없음
```

## 사용 방법

```
/review wiki/meetings/2026-06-25-온보딩개선회의.md
```

## 프로세스

1. **회의록 읽기**
   - 원본 회의록 파일 읽음
   - 모든 결정, 액션, 용어 추출

2. **메타 파일 비교**
   - decisions.md의 해당 항목 확인
   - actions.md의 해당 항목 확인
   - glossary.md의 해당 항목 확인

3. **4가지 검증 수행**
   - Decisions 검증
   - Actions 검증
   - Glossary 검증
   - 종합 검증

4. **리뷰 결과 제시**
   - 각 섹션별 상세 평가
   - 통과/경고/오류 구분
   - 개선 제안

## 핵심 규칙

### ✅ 검증해야 할 것

- 회의록 내용과 wiki 내용의 일치도
- 출처 링크([[YYYY-MM-DD]]) 정확성
- 누락된 결정/액션/용어
- 액션의 상태 추적 (특히 오래된 액션)

### ⚠️ 주의할 점

- 사람이 검토 후 수정할 수 있도록 조언 형태로 제시
- "절대 틀렸다"가 아닌 "확인 필요"로 표현
- 원본 회의록 의도 존중 (과도한 해석 금지)

