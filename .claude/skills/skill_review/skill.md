# Wiki Harness 통합 검증 스킬 (skill_review)

이 스킬은 **기계 검증**과 **LLM 검증**을 한 번에 수행합니다.

## 목적

wiki에 회의록을 적재한 후, 다음 순서로 검증:
1. **Stage 1**: 기계 검증 (구조, 포맷, 파일명)
2. **Stage 2**: LLM 검증 (컨텐츠, 의미, 누락)
3. **Stage 3**: 종합 리포트 생성

## 사용 방법

```
/skill_review wiki/meetings/YYYY-MM-DD-제목.md
```

## 전체 프로세스 (3단계)

### Stage 1: 기계 검증 (Mechanical Validation)

**역할**: 자동화된 구조 및 포맷 검증

**전제 조건**:
- `/ingest` 스킬이 이미 실행되어 메타 파일이 생성됨
- decisions.md, actions.md, glossary.md, index.md가 모두 존재

**검증 항목**:
1. **Frontmatter 검증**
   - 모든 D 파일의 frontmatter 완성도 확인
   - 필수 필드: 상태, 담당, 출처

2. **스키마 구조 검증**
   - D 파일의 필수 섹션 (결정 내용, 검토한 대안, 근거, 수정 기록)
   - actions.md의 필수 메타데이터 (담당, 기한, 상태, 출처)
   - index.md의 상태 항목 (마지막 D, A 번호)

3. **파일명 규칙 검증**
   - D-XXXX-제목.md 형식
   - YYYY-MM-DD-제목.md 형식

4. **출처 링크 검증**
   - 모든 진술에 [[YYYY-MM-DD]] 포함 여부
   - 메타데이터 행의 출처 링크 누락 감지

5. **ID 형식 검증**
   - D-0001 형식 (4자리)
   - A-0001 형식 (4자리)

**실행 명령어**:
```bash
python scripts/validate.py
```

**출력**:
```
✅ 오류: N개 (개선 필수)
⚠️ 경고: N개 (확인 권장)
```

**다음 단계로**:
- ❌ 오류가 있으면 → 오류 항목 수정 후 재실행
- ✅ 오류 0개, 경고만 있으면 → Stage 2로 진행

---

### Stage 2: LLM 검증 (Content Validation)

**역할**: 의미 수준의 컨텐츠 검증

**검증 범위**:

#### 2-1. Decisions 검증
- ✅ 모든 결정이 기록되었는가?
- ✅ 회의록에 없는 내용이 decisions.md에 추가되었는가?
- ✅ 각 결정에 정확한 출처([[YYYY-MM-DD]])가 있는가?
- ✅ 결정 내용이 원문과 일치하는가?
- ✅ 대안 검토가 정확하게 기록되었는가?

**출력 형식**:
```
📋 Decisions Review

✅ 통과: 3/3 결정
⚠️ 경고: 1개
  - D-XXXX: 내용이 약간 다름

❌ 누락: 
  - "결정명" (D 파일 없음)
```

#### 2-2. Actions 검증
- ✅ 모든 액션이 기록되었는가?
- ✅ 회의록에 없는 액션이 추가되었는가?
- ✅ 담당자가 정확하게 기록되었는가?
- ✅ 기한이 정확하게 기록되었는가?
- ✅ 액션의 상태가 정확하게 추적되었는가?

**상태 추적 확인**:
```
- 신규 액션 → 상태: 진행중/대기중
- 완료된 액션 → 상태: 완료
- 기한 연장 → 새 A 항목 또는 최근 업데이트
- 중단된 액션 → 상태: 취소됨/보류
```

**출력 형식**:
```
✅ Actions Review

✅ 통과: 4/5 액션
⚠️ 경고: 1개 (상태 추적)
  - A-XXXX: 기한이 회의록과 다름

❌ 조용한 사라짐:
  - A-XXXX: 마지막 업데이트 90일 이상 전
```

#### 2-3. Glossary 검증
- ✅ 회의록에서 새로 나온 용어가 모두 기록되었는가?
- ✅ 용어의 정의가 정확한가?
- ✅ 신규 약어/팀용어의 출처가 정확한가?

**출력 형식**:
```
📖 Glossary Review

✅ 통과: 4/4 용어
⚠️ 경고: 1개
  - UX: 정의가 불충분

❌ 누락:
  - "QA" (glossary에 없음)
```

#### 2-4. 종합 검증
- ✅ 회의록에만 있는 내용? (wiki에서 빠진 것)
- ✅ wiki에만 있는 내용? (회의록에 없는데 생성한 것)
- ✅ 의역된 부분? (원문과 의미가 다른 부분)
- ✅ 중요한 컨텍스트 누락?

**출력 형식**:
```
🎯 종합 검증

✅ 종합 평가: 통과 (98% 정확도)

⚠️ 주요 경고:
1. A-0001과 D-0007의 연관성이 명시되지 않음
2. 예산 제약이 근거에 포함되지 않음

❌ 치명적 오류: 없음
```

---

### Stage 3: 종합 리포트 생성

**결과 정리**:
```
════════════════════════════════════════
✅ Wiki 통합 검증 완료

회의록: 2026-06-25 온보딩 개선회의

--- 기계 검증 ---
❌ 오류: 0개
⚠️ 경고: 2개

--- LLM 검증 ---
✅ Decisions: 통과 (3/3)
✅ Actions: 통과 (5/5, 경고 1개)
✅ Glossary: 통과 (4/4)
✅ 종합: 통과 (98% 정확도)

--- 최종 평가 ---
상태: ✅ PASS (개선 권장: 경고 3개)
════════════════════════════════════════
```

## 실행 체크리스트

### Before (사전 준비)
- [ ] 회의록 파일이 wiki/meetings/에 저장됨
- [ ] /ingest가 이미 실행됨

### During (검증 진행)
- [ ] Stage 1: `python scripts/validate.py` 실행
  - [ ] 오류 해결 (필수)
  - [ ] 경고 검토 (권장)
- [ ] Stage 2: `/skill_review` 실행
  - [ ] Decisions 검증 완료
  - [ ] Actions 검증 완료
  - [ ] Glossary 검증 완료
  - [ ] 종합 검증 완료
- [ ] Stage 3: 리포트 생성 및 검토

### After (완료)
- [ ] 모든 오류 수정됨
- [ ] 경고 확인됨
- [ ] 최종 commit 준비

## 주요 차이점

### Stage 1 (기계 검증)
- ✅ Frontmatter, 스키마 검증
- ✅ 파일명, ID 형식 검증
- ✅ 자동화된 규칙 체크
- ❌ 의미 검증 불가

### Stage 2 (LLM 검증)
- ✅ 회의록과의 비교
- ✅ 의미, 누락, 오류 감지
- ✅ 상태 추적 검증
- ❌ 형식 검증 (Stage 1에서 이미 완료)
